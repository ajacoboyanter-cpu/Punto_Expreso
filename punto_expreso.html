Ingeniería de software

Diseño de la Base de Datos Relacional

Estructura formal con 5 tablas en MySQL (InnoDB), normalizada en 3FN para registrar clientes, productos, pedidos, detalles transaccionales y opiniones de satisfacción.

📥 Descargar database.sql 📖 Ver Diccionario de Datos Completo

CLIENTES

PK id_cliente
  • id_cliente INT (PK)
  • nombre VARCHAR(50)
  • apellido VARCHAR(50)
  • correo VARCHAR(100) UQ
  • telefono VARCHAR(20)
  • fecha_registro DATE

Guarda la información de contacto y usuarios registrados.

PRODUCTOS

PK id_producto
  • id_producto INT (PK)
  • nombre_producto VARCHAR(100)
  • categoria VARCHAR(50)
  • descripcion TEXT
  • precio DECIMAL(10,2)
  • disponibilidad ENUM

Catálogo del menú con precios oficiales de la cafetería.

PEDIDOS

PK FK id_cliente
  • id_pedido INT (PK)
  • id_cliente INT (FK)
  • fecha_pedido DATE
  • total DECIMAL(10,2)
  • estado ENUM

Encabezado de orden vinculada al cliente (1:N).

DETALLE_PEDIDO

PK FK Ped FK Prod
  • id_detalle INT (PK)
  • id_pedido INT (FK)
  • id_producto INT (FK)
  • cantidad INT
  • subtotal DECIMAL(10,2)

Tabla intermedia que resuelve la relación N:M entre Pedidos y Productos.

OPINIONES

PK FK id_cliente
  • id_opinion INT (PK)
  • id_cliente INT (FK)
  • calificacion INT (1 a 5)
  • comentario TEXT
  • fecha DATE

Reseñas y valoraciones de satisfacción dejadas por clientes (1:N).

RELACIONES

3FN
  • CLIENTES ➔ PEDIDOS 1 : N
  • PEDIDOS ➔ DETALLE 1 : N
  • PRODUCTOS ➔ DETALLE 1 : N
  • CLIENTES ➔ OPINIONES 1 : N
  • PEDIDOS ⮂ PRODUCTOS N : M

Llaves foráneas con integridad referencial activa.

1:N Clientes a Pedidos & Opiniones: Un cliente puede registrar múltiples compras y aportar varias reseñas en el portal web.
N:M Pedidos a Productos (Tabla Intermedia): Un pedido contiene múltiples productos y un producto se vende en muchos pedidos; se resuelve con detalle_pedido calculando cantidad y subtotal.
